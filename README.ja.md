# kojo-ext-square

[English](README.md)

Square の販売者アカウントで何か起きたら [kojo](https://github.com/loppo-llc/kojo) のエージェントを起こす拡張パッケージ。

- **新しい注文**、注文の **完了** / **キャンセル**
- 決済の **完了**、**失敗 / キャンセル**
- **返金** (新規、およびステータスの変化)
- 1 回のポーリングで見つかったものは **まとめて 1 ターン** でエージェントに渡る。エージェントがまだ作業中なら、次の分は **実行中のターンに追加** される
- イベントの種類・最低金額・店舗 (ロケーション) で絞り込める

Square の API を **ポーリング** するだけで、webhook も公開 URL も使わない。モデルを自分で呼ぶこともない。エージェントに届くのは「注文 X、1,200 JPY、完了、渋谷店」といった短い一覧で、明細・顧客・支払い方法などの詳細は、必要ならエージェントが **Square MCP サーバー** で調べる。

## 必要なもの

- kojo **v0.135.0 より新しいビルド** (`chat:session` 権限と拡張機能の secret 設定が必要)
- Square の販売者アカウントと、そのアクセストークン
- 詳細を見るために、エージェントに [Square MCP サーバー](https://github.com/square/square-mcp-server) も設定しておくとよい。なくても動くが、エージェントには 1 行の要約しか見えない

## 1. Square 側の準備

1. [Square Developer Console](https://developer.squareup.com/apps) を開き、アプリケーションを作る (既存のものでもよい)
2. **Credentials** で **Production** (テストデータで試すなら **Sandbox**) を選び、**アクセストークン** をコピーする

Developer Console の個人用アクセストークンはそのアカウントへのフルアクセスを持つ。OAuth トークンを使う場合は次の権限が必要:

| 権限 | 用途 |
| --- | --- |
| `ORDERS_READ` | SearchOrders |
| `PAYMENTS_READ` | ListPayments, ListPaymentRefunds |
| `MERCHANT_PROFILE_READ` | ListLocations (店舗名の表示と、店舗 ID 未指定時の店舗一覧) |

> トークンで売上が読める。チャットやリポジトリに貼らない。漏れたら Developer Console で差し替える。

本番用と sandbox 用のトークンはそれぞれの環境でしか使えないので、**環境** はトークンに合わせる。

一部の店舗だけを監視するには店舗 ID が要る。Developer Console の **Locations**、または Square データの **アカウントと設定 → 店舗情報** で確認できる。

## 2. kojo 側の設定

1. kojo の **設定 → 拡張機能** を開く
2. **リポジトリ URL** に `https://github.com/loppo-llc/kojo-ext-square` を入れて調べるボタンを押す
3. 要求される権限 (`chat:session` — 専用セッションでエージェントと会話する) を確認してインストールを承認する
4. インストール済みの一覧で **Square** を開き、起こしたいエージェントで有効にする
5. そのエージェントの設定の **Access token** にアクセストークンを貼り、**Environment** を選んで保存する

保存するとそのエージェント用のサービスが起動する。最初のポーリングは「今」を起点として記録し、インストール前に起きたことは通知しない。

トークンは kojo の資格情報ストアに暗号化して保存され、以後 UI にも API にも表示されない。

**どのエージェントが起こされるか**: この拡張機能を有効にしたエージェント。有効にしたエージェントごとにポーラー・監視位置・設定が独立しているので、2 体のエージェントで別々の Square アカウントを見ることも、同じアカウントを別の絞り込みで見ることもできる。

### 設定項目

| 設定 | 既定値 | 説明 |
| --- | --- | --- |
| Access token | — | 必須。Square のアクセストークン |
| Environment | production | `production` (connect.squareup.com) または `sandbox` (connect.squareupsandbox.com) |
| Location IDs | 空 | 監視する店舗 ID (カンマ区切り)。空ならアカウントの店舗のうち無効 (INACTIVE) でないものすべて。ID として読めるものが 1 つもないリストは何も監視しない (エージェントに警告が届く) |
| Poll interval (seconds) | 30 | Square に変化を問い合わせる間隔 (10〜3600) |
| Minimum amount | 0 | この金額以上のイベントだけ通知する。通貨の主単位で指定 (`1000` = 1,000 円または 1,000 ドル)。各イベントの通貨のまま比較する。警告は常に通知する |
| New orders | オン | `order.created` |
| Orders completed | オン | `COMPLETED` への `order.state_changed` |
| Orders canceled | オン | `CANCELED` への `order.state_changed` |
| Payments completed | オン | `payment.completed` |
| Payments failed or canceled | オン | `payment.failed` |
| Refunds | オン | `refund` |

## エージェントに届くもの

何か見つかったポーリング 1 回につき 1 通、kojo 画面のチャットとは別の専用セッション (`square`) に届く:

```
[Square プラグイン (kojo-ext-square) からの自動通知]
Square で 3 件の動きがありました。詳細 (明細・顧客・決済内容など) は Square MCP で確認してください。

- order.created | id=ORDER1 | 1,200 JPY | state=OPEN | items=コーヒー×2 | location=渋谷店 (L1)
- payment.completed | id=PAY1 | 1,200 JPY | state=COMPLETED | order=ORDER1 | location=渋谷店 (L1)
- refund | id=REF1 | 200 JPY | state=PENDING | payment=PAY0 | location=渋谷店 (L1)
```

一緒に渡すシステムプロンプトの追記 (英語) で、このターンは拡張機能が始めたこと、詳細は Square MCP にあること、返答はどこにも届かないことをエージェントに伝える。誰かに知らせる (Slack に書く、メモを残す、客に返信する) なら、エージェントが自分のツールで行う。

| イベント | 条件 |
| --- | --- |
| `order.created` | 前回のポーリング以降に作られた注文、または `DRAFT` から出た注文。下書き自体は通知しない |
| `order.state_changed` | 既知の注文の状態が変わった (`state=OPEN→COMPLETED`)、または初めて見た時点で `COMPLETED` / `CANCELED` で、インストール後に閉じられた注文 |
| `payment.completed` | 決済が `COMPLETED` になった (インストール前のカードのオーソリがインストール後にキャプチャされた場合を含む) |
| `payment.failed` | 決済が `FAILED` または `CANCELED` で終わった (インストール後の取り消しを含む) |
| `refund` | 新しい返金、返金のステータス変化、またはインストール前の返金がインストール後に確定したもの。決済の返金額が増えたのにその決済の返金レコードがまだ見えていない場合も返金として通知し、あとから現れた返金レコードを新しい返金として重ねて通知することはない |
| `plugin.warning` / `plugin.recovered` | 拡張機能自身の不調 (後述) |

一覧は 50 行まで。残りは件数だけ示す (「ほか N 件」)。

## 仕組み

- **ポーリング**: 間隔ごとに SearchOrders (1 リクエスト最大 10 店舗)、ListPayments (1 リクエスト 1 店舗)、ListPaymentRefunds を `updated_at` で絞って古い順に呼び、ページングのカーソルをたどる。すべてのリクエストに `Square-Version: 2026-09-16` を付ける
- **監視位置**: ストリーム (注文・決済・返金) ごとに、見た中で最新の `updated_at` をカーソルとして持つ。次のポーリングはカーソルの **2 分前** から問い合わせ、Square の結果整合な検索に遅れて現れる行も拾う。2 回返ってきたものは、オブジェクトごとに覚えている指紋 (version / ステータス) で見分けて再通知しない。覚えておく数には上限がある (ストリームごとに 5,000 件、古いものから捨てる)。ページ上限 (1 クエリ 40 ページ) に達したポーリングは、追いつくまで重なり幅なしで止まったところから再開する
- **再起動しても失わない**: 監視位置、覚えている集合、まだ届けていないイベントは、拡張機能のデータディレクトリの `state.json` にまとめて保存する (一時ファイルに書き、同期し、rename する)。監視位置は、見つけたイベントをキューに入れるのと同じ書き込みでしか進まない。失敗したストリームは位置を保ったまま次回やり直す
- **配送**: キューのイベントを 1 通のメッセージにする。実行中のターンがなければ、セッション `square` で新しいターンを始める。自分が始めたターンがまだ実行中なら、そのターンに **steer** (追加) する。バックエンドが steer に対応していなければ、ターンが終わるのを待って次のターンにする。kojo が busy・停止中・エラーを返した場合は、イベントをキューに残したままバックオフして再試行する。イベントがキューから消えるのは kojo が受け付けたときだけ (なので間の悪いタイミングで落ちると通知が重複することはあるが、失われることはない)。キューの上限は 1,000 件で、あふれたら古いものから捨て、次のメッセージで件数を伝える
- **レート制限とエラー**: 429 と 5xx は指数バックオフとジッターで再試行する (`Retry-After` に従う)。401 / 403 は再試行しない
- **警告**: Square がトークンを拒否した (401) らすぐに、それ以外の理由でポーリングが 5 回続けて失敗したら 1 回だけエージェントに伝える。ポーリングが戻ったら復旧を 1 回伝える。トークンが拒否されている間は、ポーリングを 5 分おきに落とす

## 困ったとき

| 症状 | 確認すること |
| --- | --- |
| 何も届かない | トークンは正しい **環境** 用のものを保存したか。拡張機能とエージェントの両方が有効か。通知されるのはインストール **後** に起きたことだけ。絞り込み (最低金額、店舗 ID) が厳しすぎないか |
| 401 を含む `plugin.warning` | トークンが間違っている、失効している、または別の環境のもの。新しいトークンを保存する |
| 403 を含む `plugin.warning` | OAuth トークンに 1 節の権限が足りない |
| 店舗名が出ない | `MERCHANT_PROFILE_READ` がない。代わりに ID を表示する |
| ログに `no Square access token configured` | トークンがまだ保存されていない。サービスは待機している |

ログは kojo 本体のログに `extension=square` 付きで出る。

## 制限

- **さかのぼらない**: 最初のポーリングはインストール時点 (または保存状態を失った時点) から始まる
- **オフラインの POS 売上** は Square に届くまで最大 72 時間かかることがある。届いたときにはその注文がカーソルの 2 分前の窓から外れていた場合、通知されない
- Square の検索は結果整合なので、変化が 1 回遅れのポーリングで現れることがある
- webhook を使わないので、遅れは最大でポーリング間隔 1 回分 + Square 自身の遅れ
- 非常に忙しいアカウント (1 回のポーリングでストリームあたり 40 ページを超える変化) は数回のポーリングに分けて追いつく
- 作成から 1 年を超えた決済・返金は見ない (Square のこれらの一覧の `begin_time` の既定値)。Square はそこまで古い決済の返金を受け付けないので、実際に通知すべきものを取りこぼすことはない

## 開発

```sh
make test    # go vet + go test
make build   # 全プラットフォーム向けのバイナリを bin/ 以下にビルド
```

kojo は拡張パッケージを `git clone` で入れるだけでビルドしないので、バイナリはリポジトリにコミットしてある。コードを変えたら `make build` を実行し、`bin/` も一緒にコミットして、`kojo-package.json` の `version` を上げる。

テストは Square と kojo の代わりに `httptest` を使い、実際の Square は呼ばない。
